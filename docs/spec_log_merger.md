# ロガーCSV・UART CSV統合ツール 仕様書（v4）

## 1. 目的

GRAPHTEC GL240（データロガー）のCSVと、マイコンからUART経由で受信したCSVを読み込み、
時刻をそろえて1つのExcelファイル（.xlsx）にまとめる。
まとめる前にGUIで、間隔・出力する項目・ラベル・値の換算・グラフ・出力先を調整できるようにする。

## 2. 動作環境・配布形態

- 言語：Python 3.x
- 主なライブラリ：pandas、openpyxl、GUIは tkinter（標準ライブラリ）
- 対象OS：Windows
- 配布形態：PyInstaller で exe 化する
  - `--onedir` 形式（フォルダ配布）とする。`--onefile` は起動のたびに一時フォルダへの展開が発生し、起動が遅くなるため使わない
  - Python 環境がある PC では `python main.py` でも同じように動くこと
  - exe のビルド手順（コマンド）を README に記載する
- 調整のしやすさのため、初期値は exe の外の設定ファイルに持つ（2.1）

### 2.1 設定ファイル `config.json`

exe（または `main.py`）と同じフォルダに置く。exe を作り直さずに初期値を変えられるようにするため。
ファイルがない、または壊れている場合は、プログラム内の既定値で動作し、既定値で `config.json` を作り直す。

保持する内容：

- UART各列の設定（採用するか、ラベル、係数、オフセット）
- ロガーCHの設定（CH番号ごとに、採用するか、ラベル、係数、オフセット）と、
  保存された設定がないCH用のラベル書式（例：`{ch}({unit})`）
- 経過時間(s)列のラベル
- グラフの設定（5.2.4）
- 画面1の「参照」ダイアログで最後に開いたフォルダ（UART用・ロガー用それぞれ）
- 出力ファイル名の書式（例：`解析_{start:%y%m%d-%H%M%S}.xlsx`）
- 行数の警告しきい値（100,000）と上限（1,000,000）

### 2.2 前回設定の保存と復元

画面2で調整した内容を `config.json` に保存し、次回の初期値として使う。

- **保存のタイミング**：「Excelに出力」が成功したとき
  （出力をキャンセル・失敗した場合や、出力せずに終了した場合は保存しない）
- **保存する項目**
  - 5.2.3 の各項目の採用・ラベル・係数・オフセット
  - 5.2.4 のグラフ設定
  - 画面1で選んだファイルのフォルダ（次回「参照」ダイアログの初期フォルダにする）
- **保存しない項目**（毎回、読み込んだCSVから決める）
  - UART間隔・ロガー間隔（初期値は常にCSVから取得）
  - 出力先フォルダ（初期値は常にUART CSVのフォルダ）
  - ファイル名（初期値は常に書式から生成）
- **保存のキー**
  - UART列は元の列名（例：`voltage_mV`）、ロガーはCH番号（例：`CH1`）をキーにする。ラベルはキーにしない（ラベルを変えても設定が引き継がれるように）
  - グラフの第1軸・第2軸も、ラベルではなくこのキーで保存する
- **復元時の扱い**
  - 保存された設定があれば、それを画面2の初期値にする
  - 今回のCSVにない列・CHの設定は、画面には出さないが `config.json` からは消さない（CH数を一時的に減らして測定した場合などに備えるため）
  - 保存された設定がない列・CHは既定値（5.2.3の表、ロガーはラベル書式）を使う
  - グラフで選ばれていた項目が今回のCSVにない、または採用されていない場合、その欄は未選択（エラー表示）にする
  - ロガーCHの単位が前回と異なる場合（例：CH1が前回[mV]、今回[V]）は、ラベルと係数が合わなくなるおそれがあるので、画面2の読み込み結果欄に警告を出す。
    そのため、ロガーCHの保存には単位も記録する
- **初期値に戻す**：画面2に「初期値に戻す」ボタンを置く。押すと確認ダイアログの後、5.2.3・5.2.4 をプログラム内の既定値に戻す（`config.json` は次に出力が成功したときに上書きされる）
- `config.json` への書き込みに失敗しても（読み取り専用フォルダなど）Excel出力は成功扱いとし、「設定を保存できませんでした」と通知する

## 3. 入力ファイル

### 3.1 UART CSV（例：`log40.csv`）

- 文字コード：UTF-8、改行CRLF、1行目がヘッダ
- 列：`pc_timestamp, t_ms, elapsed_ms, voltage_mV, current_mA, cap_mAh, cap_max_mAh, soc_percent, soh_percent, temp_C`
- `pc_timestamp` は PC の時刻（形式 `YYYY-MM-DD HH:MM:SS.ffffff`）で、**本ツールで時刻の基準として使う唯一の時刻**とする
  - マイコン側の時刻（`t_ms`、`elapsed_ms`）は時刻合わせには使わない（出力する項目としては選べる）
- 列が欠けている・数値に変換できない行はスキップし、スキップ件数を画面2に表示する

### 3.2 ロガー CSV（例：`260924-090155.CSV`）

- 文字コード：Shift-JIS（CP932）、改行CRLF
- 構成：ヘッダ部（可変長）＋データ部
  - ヘッダ部から以下を取得する
    - `モデル`（例：GL240）
    - `測定間隔`（例：`200ms`。`1s`、`1min` 等の単位もありうるので ms に換算する）
    - `アンプ設定` セクションの各CHの信号名と単位（例：CH1=[mV]、CH2=[V]）
  - `測定値` の行の次の2行がヘッダ（項目名行と単位行）、その次からがデータ部
- データ部の列：`番号, 日付/時間, ms, CH1, CH2, …, Alarm1-10, AlarmOut`
  - CH数は設定によって1〜10で変わるため、ヘッダから動的に判定する
  - 数値は `+  0.28` のように符号とスペースを含むので、スペースを除去してから数値化する
  - 数値化できない値（レンジオーバー表示など）は空欄として扱う
  - Alarm列は出力しない
- **ロガーの内部時刻（`日付/時間`、`ms` 列）は信用しないため使わない**
  - ロガーの各行の経過時間は `(番号 − 1) × ロガー間隔` とみなす

## 4. 時刻合わせとデータの取捨選択

### 4.1 用語と開始点

- UARTのCSV取得開始とロガーの計測開始は同時に行う運用とする
- **UARTの1行目の `pc_timestamp` を経過時間0、ロガーの1行目（番号1）も経過時間0**とする
- UART各行の経過時間 `tU` = その行の `pc_timestamp` − 1行目の `pc_timestamp`（ms）
- ロガー各行の経過時間 `tL` = `(番号 − 1) × ロガー間隔`（ms）
- UART間隔・ロガー間隔は、画面2でユーザーが確認・編集した値を使う

### 4.2 UART受信の欠落の検出と補完

1. UARTの隣接行について、`pc_timestamp` の差が「UART間隔 × 1.5」を超える箇所を欠落とみなす
2. 欠落1箇所あたりの欠落行数 `n = round(差 ÷ UART間隔) − 1`
3. 欠落箇所には `n` 行の**欠落行**を挿入する
   - 欠落行の経過時間：直前の行の `tU` ＋ UART間隔 × 1, 2, …, n
   - 欠落行のUART側の値：**空欄**（6.2参照）
4. 欠落の件数・発生位置（行番号・時刻）・補完した行数を画面2に警告表示する
5. 差が「UART間隔 × 0.5」未満の行（二重受信など）は後の行を捨て、件数を画面2に表示する

### 4.3 間隔の違いの吸収

欠落補完後のUARTデータとロガーデータについて、間隔の長い方を基準とし、短い方から時刻の最も近い行を1行ずつ選ぶ。
時刻は常に4.1の経過時間で比べる（行番号の単純な間引きにはしない。受信のゆらぎや欠落があっても対応がずれないようにするため）。

- **UART間隔 ≧ ロガー間隔 の場合（例：UART 1000ms、ロガー 200ms）**
  - UARTの全行（欠落行を含む）を基準行とする
  - 各基準行について、ロガーの行番号 `round(tU ÷ ロガー間隔)`（0始まり）の行を採用する
  - 通常は「ロガーを5行ごとに採用」と同じ結果になる
- **UART間隔 ＜ ロガー間隔 の場合（例：UART 100ms、ロガー 200ms）**
  - ロガーの全行を基準行とする
  - 各基準行について、`tU` が `tL` に最も近いUART行を採用する。ただし差が「UART間隔 × 0.5」を超える場合は、UART側を空欄にする
- 間隔が等しい場合は前者の扱いとする
- どちらかのデータが尽きた時点で打ち切る

### 4.4 解析シートの経過時間

- 出力する経過時間は**UART CSVの時刻（`pc_timestamp`）から求めた `tU`** を使う
  - 欠落行は4.2の補完値
  - ロガーが基準で、対応するUART行がない行は `tL`
- 経過秒数 = 経過時間(ms) ÷ 1000（小数第3位まで）

## 5. GUI

画面は2つ。画面1でファイルを選び、読み込み後に画面2で出力内容を調整してから出力する。

### 5.1 画面1：ファイル選択

```
┌ ファイル選択 ─────────────────────────────┐
│ UART CSV    [C:\...\log40.csv          ] [参照] │
│ ロガー CSV  [C:\...\260924-090155.CSV  ] [参照] │
│                                   [読み込み]     │
└──────────────────────────────────┘
```

- 「参照」でファイル選択ダイアログを開く（拡張子 .csv / .CSV）
- 両方選ばれるまで「読み込み」ボタンは無効
- 「読み込み」で両ファイルを解析し、成功したら画面2へ進む
- 形式が想定と違う等で読み込めない場合は、原因がわかるメッセージを出して画面1にとどまる

#### 5.2.1 読み込み結果

- 各ファイルの行数、開始・終了時刻、ロガーのモデル名とCH数
- UARTのスキップ行数、重複で捨てた行数
- 欠落の警告（4.2）。「詳細」で欠落箇所の一覧（行番号・時刻・補完行数）を別ウィンドウに表示する

#### 5.2.2 間隔

- 「UART間隔(ms)」「ロガー間隔(ms)」の入力欄
- 初期値
  - UART：`pc_timestamp` の隣接行差の中央値を 100ms 単位に丸めた値
  - ロガー：ヘッダの `測定間隔`
- 値を変更したら、欠落検出・基準側・出力予定行数をその場で再計算して表示する
- 0以下や数値以外は入力エラーとし、「Excelに出力」ボタンを無効にする

#### 5.2.3 出力する項目

- UART CSVの数値列（`pc_timestamp` 以外のすべて）と、ロガーの全CHを1行ずつ一覧表示する
- 各行の構成
  - **採用チェックボックス**：チェックした列だけを解析シートに出力する
  - **ラベル入力欄**：解析シートの見出し・グラフの系列名に使う文字列
  - **係数・オフセット入力欄**：解析シートに出力する値を `元の値 × 係数 ＋ オフセット` に換算する（初期値 係数1・オフセット0）
    - 例：電圧を mV から V にする → 係数 0.001、ラベルを `電圧(V)` に変更
  - 採用チェックが外れている間は、その行のラベル・係数・オフセット欄を無効（グレー）にする
- 「経過時間(s)」は常に出力する固定行。採用チェックは外せない（グラフの横軸に使うため）。ラベルのみ編集可、係数・オフセットはなし
- 初期状態は `config.json` の前回設定（2.2）。前回設定がない場合の既定値は sample.xlsx 準拠：

| 元の列 | 採用 | 初期ラベル | 係数 | オフセット |
|---|---|---|---|---|
| 経過時間(s) | ✓（固定） | 経過時間(s) | ― | ― |
| t_ms | | t_ms | 1 | 0 |
| elapsed_ms | ✓ | time(ms) | 1 | 0 |
| voltage_mV | ✓ | 電圧(mV) | 1 | 0 |
| current_mA | ✓ | 電流(mA) | 1 | 0 |
| cap_mAh | ✓ | CAP(mAh) | 1 | 0 |
| cap_max_mAh | | CAP_MAX(mAh) | 1 | 0 |
| soc_percent | ✓ | SOC(％) | 1 | 0 |
| soh_percent | | SOH(％) | 1 | 0 |
| temp_C | ✓ | 温度(℃) | 1 | 0 |
| ロガー CHn | ✓ | CHn(単位) 例：CH1(mV) | 1 | 0 |

- 入力チェック（エラー時は該当欄を赤くし、「Excelに出力」ボタンを無効にする）
  - 採用した項目のラベルが空欄
  - 採用した項目どうしでラベルが重複
  - 係数・オフセットが数値でない
- 項目数が多い場合（ロガー10CH時など）は一覧部分をスクロール可能にする

#### 5.2.4 グラフ

- グラフを1行1つとして一覧で設定する。「＋グラフを追加」で行を追加、「削除」で行を削除
- 各グラフに**第1軸（左の縦軸）と第2軸（右の縦軸）のデータを1つずつ**選ぶ
  - 選択肢は、5.2.3で採用チェックが入っている項目（経過時間(s)を除く）。表示はラベル
  - 第1軸は必須。第2軸は「なし」を選べる
  - 第1軸と第2軸に同じ項目は選べない
- 5.2.3で採用を外した項目やラベルを変更した項目は、選択肢に即時反映する。選択中の項目の採用が外れた場合は、そのグラフの欄を未選択（エラー表示）にする
- グラフが0個でもよい（その場合 `グラフ` シートは作らない）
- 初期状態は `config.json` の前回設定（2.2）。前回設定がない場合の既定値：グラフ1＝第1軸 電圧(mV)・第2軸 電流(mA)

#### 5.2.5 出力先

- 「フォルダ」入力欄と「参照」ボタン（フォルダ選択ダイアログ）
  - 初期値：**UART CSVファイルがあるフォルダ**
- 「ファイル名」入力欄
  - 初期値：`解析_<UART 1行目のpc_timestamp YYMMDD-HHMMSS>.xlsx`
  - 拡張子 `.xlsx` がなければ自動で付ける
  - ファイル名に使えない文字（`\ / : * ? " < > |`）が含まれていたらエラーにする
- 同名ファイルがある場合は上書き確認ダイアログを出す

#### 5.2.6 ボタン

- 「初期値に戻す」：2.2 参照
- 「戻る」：画面1に戻る（選択済みのファイルパスは保持）
- 「Excelに出力」
  - 行数チェック（7章）を行う
  - 出力中は進捗（またはビジー表示）を出し、ボタンを無効にする。GUIが固まらないよう、出力処理は別スレッドで行う
  - 完了・失敗をメッセージで知らせる。完了時は「フォルダを開く」ボタンを付ける
  - 成功時に現在の設定を `config.json` に保存する（2.2）
  - 出力先のファイルがExcelで開かれていて保存できない場合は、その旨を表示する

## 6. 出力（Excel）

### 6.1 シート構成

| シート名 | 内容 |
|---|---|
| `解析` | まとめたデータ（6.2） |
| `グラフ` | グラフ（6.3）。グラフが0個の場合は作らない |
| UART CSVのファイル名（拡張子なし） | UART CSVの全データをそのまま貼り付け（換算・補完はしない） |
| ロガー CSVのファイル名（拡張子なし） | ロガー CSVの全内容をそのまま貼り付け（換算はしない） |

- シート名はExcelの制限（31文字以内、`\ / ? * [ ] :` 不可）に合わせて切り詰め・置換する

### 6.2 `解析` シートのレイアウト

| セル | 内容 |
|---|---|
| A1 / B1 | `測定日時` / UART 1行目の `pc_timestamp`（書式 `yyyy/mm/dd hh:mm:ss`） |
| A2 / B2 | `測定機` / ロガーのモデル名（例：GL240） |
| 3〜4行目 | 空行 |
| A5 | `マイコン内部データ(UART)` |
| A6〜 | 経過時間(s)、続いて採用したUART列（画面2の並び順）。6行目が見出し（画面2のラベル）、7行目からデータ |
| UART列の右に1列空けて5行目 | `測定値` |
| 同6行目〜 | 採用したロガーCH列。6行目が見出し、7行目からデータ |

- 値は5.2.3の係数・オフセットで換算した後の値を、数値型で書き込む（文字列にしない）
- **欠落行・対応行がない箇所・ロガーの数値化できない値は空欄**にする
  - 0を入れると、グラフで0まで落ちる線が描かれてしまうため。空欄にすると、グラフではその部分が途切れて表示される
- 欠落で補完した行は、行全体を薄い灰色で塗り、欠落行とわかるようにする

### 6.3 `グラフ` シート

- 5.2.4で設定したグラフを、設定順に縦に並べて配置する
- 種類：散布図（直線あり・マーカーなし）
- 横軸：`解析` シートの経過時間(s)列。横軸タイトルはその列のラベル
- 第1軸（左）：選んだ項目。縦軸タイトルはそのラベル
- 第2軸（右）：選んだ項目（「なし」の場合は作らない）。縦軸タイトルはそのラベル
- グラフタイトル：「第1軸ラベル / 第2軸ラベル」（第2軸なしの場合は第1軸ラベルのみ）
- 凡例を表示する（系列名はラベル）
- 空欄セルは「空白として表示（線を途切れさせる）」設定にする
- グラフのデータは `解析` シートのセル範囲を参照する（値をコピーしない）

## 7. 行数の制限

「Excelに出力」を押した時点で、出力する全シートのうち最も行数が多いシートの行数で判定する。
（ロガーの元データシートは、解析シートより行数が多くなる。例：UART 1000ms・ロガー 200msなら約5倍）

| 最大行数 | 動作 |
|---|---|
| 100,000行以下 | そのまま出力 |
| 100,000行超〜1,000,000行以下 | 警告ダイアログ（行数と「出力に時間がかかる可能性があります」）を出し、「続行」「キャンセル」を選ばせる |
| 1,000,000行超 | エラーダイアログを出し、出力しない |

- 画面2の「出力予定行数」表示でも、10万行超は黄色、100万行超は赤で表示する

## 9. 受け入れ条件（テスト）

- `tests/data/` に入力サンプル（UART CSV、ロガー CSV）と期待出力の xlsx を置く
- 自動テストで以下を確認する
  - ロガーヘッダの解析（モデル名、測定間隔、CH数・単位）が正しい
  - 間隔の初期値の算出が正しい
  - 時刻合わせ（4.3）で採用される行が正しい（UART 1000/ロガー 200、100/200、1000/300、等間隔の各ケース）
  - `pc_timestamp` にゆらぎ（±10ms程度）があっても、1000/200 のケースでロガーが5行ごとに採用される
  - 欠落（4.2）：UARTの行を人為的に抜いたデータで、欠落行が正しい行数・経過時間で挿入され、値が空欄になり、以降の行のロガーとの対応がずれない
  - 採用・ラベル・係数・オフセットの設定どおりに `解析` シートが出力される
  - グラフ設定どおりに `グラフ` シートにグラフが作られ、横軸が経過秒数、第2軸が設定どおりになっている
  - 行数制限（7章）の判定が正しい
  - `config.json` がない・壊れている場合に既定値で起動する
  - 出力成功時に設定が保存され、次回読み込み時に復元される。出力キャンセル・失敗時は保存されない
  - 間隔・出力先フォルダ・ファイル名は保存されず、毎回CSVから決まる
  - ラベルを変更しても、グラフ設定が元の列に対応したまま復元される
  - 前回より少ないCH数のCSVを読んで出力しても、存在しなかったCHの設定が消えない
  - ロガーCHの単位が前回と異なる場合に警告が出る
  - 「初期値に戻す」で既定値に戻る
- 期待出力は、**同時に計測した実データ**から作り直すこと（現在の sample.xlsx の2つのCSVは計測時間帯が重なっていないため）
