# デザイン依頼書：ロガーCSV・UART CSV 統合ツール（GUI）

この資料は Claude Design に GUI のデザイン改善を依頼するためのものです。
添付の `screenshots/` が現在の画面、`ui_structure.json` が画面部品の一覧（機械可読）です。

---

## 1. アプリの概要

| 項目 | 内容 |
|---|---|
| 名前 | ロガーCSV・UART CSV 統合ツール（exe 名：LogMerger） |
| 目的 | データロガー（GRAPHTEC GL240）の CSV と、マイコンから UART で受信した CSV を読み込み、時刻をそろえて 1 つの Excel（解析表＋グラフ）にまとめる |
| 利用者 | 電池・電源まわりの評価を行う技術者（社内）。毎回ほぼ同じ設定で使い、たまに項目・グラフを調整する |
| 利用環境 | Windows 10/11 のデスクトップアプリ。ノート PC（1280×720〜1920×1080）でも使う |
| 言語 | 日本語 UI |
| 使う頻度・流れ | 測定のたびに：2つの CSV を選ぶ →（必要なら）設定を少し直す →［Excelに出力］。設定は前回の値が自動で入る |

## 2. 画面の流れ

```
画面1：ファイル選択 ──［読み込み］──▶ 画面2：出力内容の調整 ──［Excelに出力］──▶ 出力中ダイアログ ──▶ 完了ダイアログ
        ▲                                  │                                              （フォルダを開く / OK）
        └──────────［戻る］────────────────┘
                                   画面2から開く補助ウィンドウ：欠落の詳細、カラーパレット
```

- 画面1と画面2は同じウィンドウ内で切り替わる（別ウィンドウではない）
- 画面2は縦に長い。ヘッダー的な固定部はなく、フッター（エラー一覧＋ボタン）だけ下に固定、それ以外は縦スクロール

## 3. 画面ごとの内容

### 3.1 画面1：ファイル選択（`01_file_select.png`）

| 部品 | 種類 | 文言・内容 | 動作・状態 |
|---|---|---|---|
| 枠 | ラベル付き枠 | 「ファイル選択」 | |
| UART CSV | ラベル＋入力欄＋ボタン | 入力欄にパス、［参照］ | ［参照］でファイル選択ダイアログ。入力欄への直接入力・ドラッグ＆ドロップ可 |
| ロガー CSV | 同上 | 同上 | 同上 |
| 案内文 | 文字（グレー） | 「CSV ファイルをこの枠にドラッグ＆ドロップできます（2つ同時も可。中身から UART／ロガーを自動判別）」 | |
| ［読み込み］ | ボタン | | 2つとも入力されるまで無効。形式エラー時はメッセージを出して画面1にとどまる |

- ドラッグ＆ドロップ：欄の上に落とすとその欄、枠内の他の場所なら中身で自動判別
- 画面1は情報量が少なく、ウィンドウの上部に小さく寄っている（下は空白）。**改善の余地が大きい**

### 3.2 画面2：出力内容の調整（`02_adjust_normal.png` ほか）

上から順に 5 つのセクション＋固定フッター。

#### (1) 読み込み結果
- 「UART : 8行 09:09:54〜09:10:01 スキップ0行 / 重複0行」
- 「ロガー: GL240 36行 2CH 測定間隔 200ms」
- 欠落の状態：「欠落なし」または「⚠ 欠落：1箇所（2行を空欄で補完）」＋［詳細］ボタン（警告色）
- 前回とロガーの単位が違うときは「⚠ CH1 の単位が前回と異なります…」の警告行が追加される

#### (2) 間隔・時間オフセット
- 1行目：UART間隔 [1000] ms　ロガー間隔 [200] ms（数値入力）
- 2行目：時間オフセット UART [0] ms　ロガー [0] ms　（＋で遅らせる。例：ロガーの変化が1秒早いときはロガーに 1000）
- 3行目：結果表示「→ UART基準・ロガーを時刻で間引き（約5行ごと） / 出力予定 8行」
  - 出力行数が 10万行超：黄色背景＋警告色、100万行超：赤背景＋エラー色
  - 入力エラー時：「間隔を正の数値で入力してください。」（エラー色）
- 値を変えると 0.25 秒後に自動で再計算

#### (3) 出力する項目（表）
列：**採用（チェック）｜元の列名｜ラベル（入力欄）｜係数（入力欄）｜グラフの色（色見本ボタン）**

- 先頭行「経過時間(s)」は固定行：チェックは常にオン（変更不可、グレー）、係数・色は「―」、ラベルのみ編集可
- UART の列（9行程度：t_ms, elapsed_ms, voltage_mV, current_mA, cap_mAh, cap_max_mAh, soc_percent, soh_percent, temp_C）
- 区切り「── ロガー ──」
- ロガーの CH（1〜10行。元の列名は「CH1 (mV)」のように単位付き）→ 10CH 時は縦に長くなる（`04_adjust_gap_10ch.png`）
- 採用チェックを外した行は、ラベル・係数・色がグレー（無効）
- 色見本ボタンを押すとカラーパレット（`06_color_palette.png`）

#### (4) グラフ（表）
列：**No｜横軸｜第1軸（左・2つまで）×2｜第2軸（右・2つまで）×2｜［削除］**、下に［＋グラフを追加］

- 1行 = 1つのグラフ（0〜数個）
- 各欄はプルダウン。選択肢は「採用中の項目のラベル」。横軸には「経過時間(s)」も入る。第1軸の2つ目と第2軸は「なし」を選べる
- 1つのグラフで同じ項目を2回選ぶとエラー
- 現状、横幅が広く（6 つのプルダウン＋削除）、狭いウィンドウでは右端が切れる

#### (5) 出力先
- フォルダ [パス] ［参照］
- ファイル名 [解析_260924-090954.xlsx]

#### 固定フッター（常に画面下に表示）
- エラー一覧（エラー色の文字、最大 6 行＋「…ほか N 件」）
- 左：［初期値に戻す］　右：［戻る］［Excelに出力］（エラーがある間は［Excelに出力］無効）

## 4. 現在のデザイン仕様

| 項目 | 値 |
|---|---|
| UI ライブラリ | Python tkinter / ttk ＋ テーマ **sv-ttk（Sun Valley, light）** ＝ Windows 11 の Fluent 風 |
| 背景 | #fafafa |
| 文字色 | #1c1c1c、無効 #a0a0a0 |
| アクセント（チェック・選択） | #005fb8 |
| エラー色 | #c42b1c（文字）、入力欄は赤い下線（sv-ttk の invalid 表示） |
| 警告色 | #9d5d00（文字）、行数警告の背景 #fff3a0、上限超えの背景 #ffc0c0 |
| 見出し | 表の列見出しは太字（9pt 相当） |
| セクション | ラベル付き枠（LabelFrame）で区切り |
| ウィンドウ | 初期 920×860、最小 480×320、リサイズ可 |
| ラベル入力欄の幅 | 20 文字（ウィンドウ幅で伸びない） |

※ スクリーンショットは Linux の仮想ディスプレイで撮影したため、フォントが Windows（Segoe UI / Yu Gothic UI）と異なります。

## 5. 現状の気になる点（改善してほしいところの例）

- 画面1がスカスカ（上部に小さな枠だけ）。ドラッグ＆ドロップできることが伝わりにくい
- 画面2が縦に長く、全体の把握がしにくい。セクションの重要度（よく触る：項目・グラフ／たまに：間隔・オフセット）が見た目で区別されていない
- 時間オフセットの説明文が長く、幅 920px で右端が切れる
- グラフ設定の行が横に長い（プルダウン 5 つ＋削除）
- エラーの場所と、フッターのエラー一覧の対応が分かりにくい
- 「読み込み結果」が文字の羅列で、要点（行数・欠落の有無）が目立たない

## 6. 実装上の制約（**デザイン案はこの範囲で実現できるものにしてください**）

デザイン案は Python の tkinter（ttk）＋ sv-ttk で実装し直します。

**使える部品**：ボタン（通常・強調=Accent）、入力欄、チェックボックス、トグルスイッチ、ラジオボタン、プルダウン（Combobox）、数値スピン、ラベル、ラベル付き枠、区切り線、タブ（Notebook）、表（Treeview）、スクロールバー、プログレスバー、スケール、色付きの四角（色見本）、単色の背景を持つ領域、画像（PNG）の表示

**できる／できないこと**
- ○ 配置の変更（横並び・2 カラム・タブ分け・折りたたみ風の開閉）、余白、文字サイズ・太さ、単色の塗り、ライト／ダークテーマ
- △ 角丸・アイコン：画像（PNG）を用意すれば可能。アイコンは絵文字や記号文字（⚠ ✓ ＋ など）なら簡単
- × 影、ぼかし、グラデーション、半透明、アニメーション、Web のような自由なカード UI、ホバーで出るツールチップの装飾
- 1 ウィンドウ内での画面切り替え（画面1 ⇄ 画面2）は維持。別ウィンドウ化は補助画面のみ
- 日本語の文言が入るので、横幅に余裕を持たせる（1280px 幅のノート PC で横スクロールなしが目標）

## 7. 変えてよいもの／変えないもの

- **変えてよい**：配置、グルーピング、セクションの順序、タブ化・折りたたみ、強調のしかた、余白、配色、文言の言い回し（意味が同じなら）、ボタンの位置
- **変えない**：機能（入力項目・操作の種類）、各入力値の意味、エラーを出す条件、画面1→画面2 の流れ
